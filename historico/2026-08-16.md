## 📝 Decisões técnicas importantes

- **Compromisso sem hora marcada**: campo novo `horaDefinida: Boolean`. Quando você não dá hora, `quando` grava o horário de fechamento do dia (`Preferencia.horaFechamentoDia`) só pra ordenar/lembrar — a UI nunca deveria mostrar isso como hora real (bug achado e corrigido, ver abaixo)
- **Cartão motivacional usa `next/og` (Satori)**, não Puppeteer — roda em runtime nodejs comum, sem headless browser. Fontes em TTF (satori não lida bem com woff2) baixadas via truque de User-Agent antigo no Google Fonts
- **Railway não tem comando de CLI pra Cron Schedule** — descoberto na hora. Contornei chamando a API GraphQL da Railway direto (`backboard.railway.com/graphql/v2`) com o token salvo em `~/.railway/config.json`, mutation `serviceInstanceUpdate(input: { cronSchedule })`. Confirmado com uma query de leitura depois — os dois serviços responderam certo

## ⚠️ Problemas encontrados e soluções

- **Bug real da IA em produção**: pedido "hoje às 12:10" foi extraído como 16:00 (alta confiança, errado mesmo assim). Corrigido o dado na mão; fica registrado que extração por LLM erra mesmo com tool-use forçado — o card de confirmação existe justamente pra isso, mas cabe conferir o horário antes de clicar ✅
- **Corrida entre correção manual e reagendamento real**: enquanto eu corrigia o horário acima direto no banco, o Marcelo testou o botão "Reagendar" no Telegram pro mesmo compromisso — as duas escritas bateram de frente, minha correção venceu por timing e sobrescreveu o reagendamento dele. Resolvido perguntando qual valor ele queria manter
- **Serviço `socrates-motivacional` crashou no primeiro deploy**: rodei `railway up` antes de configurar as env vars do serviço — ele tentou algumas vezes, falhou (`process.exit(1)` intencional do script quando falta config) e ficou "Crashed". Não é loop caro (poucas tentativas rápidas, não infinito); resolvido com `railway redeploy` depois de configurar as vars
- **Mensagem motivacional disparou fora de hora**: efeito colateral do redeploy de teste acima — como já tinha `TELEGRAM_OWNER_CHAT_ID` configurado nesse ponto, o teste mandou a imagem de verdade pro Telegram do Marcelo, não só simulou. Sem problema (ele gostou), mas registra que testar esse serviço específico sempre dispara de verdade
